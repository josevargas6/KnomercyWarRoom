## Execution order

### 1. Establish the current truth

- Inspect the existing owners of Team health, `specSource`, command
  publication/signatures, AAR stability totals, objective-event normalization,
  and tactical target construction.
- Search current tests and changelog entries before assuming the July 28 defect
  still has the same code-level cause. Preserve any later improvements.
- Record the observed starting behavior and the smallest repair path in the
  three authoritative task briefs or in a dated implementation record linked
  from them.
- Preserve the single Store, MatchRuntime, Strategist, Commander, ObjectiveIntel,
  assignment, and UI ownership model. Do not create parallel services or state.

### 2. Implement KWR-032

- Make expanded Team health visibly useful when a legal friendly unit token
  exists.
- Never compare, divide, round, stringify, or otherwise inspect a Retail secret
  health value. Pass a direct live value only to a legal native display
  primitive. Use normalized public health only when it is actually available.
- Render an explicit bounded state (`LIVE`, safe normalized text, or `UNKNOWN`)
  so direct-live and unknown are not visually identical.
- Preserve `specSource` through roster reconciliation and every assignment/Team
  projection.
- Show `(HIST)` consistently on compact Team, expanded Team, and Assignments for
  historical evidence. Do not label verified/live specialization evidence as
  historical.
- Add deterministic assertions for normalized health, direct-live health,
  unknown health, historical spec, cached spec, verified/live spec, and
  cross-surface provenance agreement.

### 3. Implement KWR-033

- Reproduce command churn with a deterministic noisy flag-event replay and
  identify the exact signature, ActivePlay, invalidation, or observation fields
  that cause materially unchanged commands to republish.
- Suppress publication when the actionable command contract is unchanged.
- Preserve immediate bypasses for real carrier changes, score changes,
  objective loss, match completion, emergency/decisive invalidation, and
  explicit reassessment.
- Retain and expose total evaluations, issued commands, replacements,
  suppressions, reversals, and ActivePlay switches. Keep the command journal
  bounded, but label retained records separately from total issued commands.
- Rename or qualify ActivePlay switches so they cannot be read as manual
  commander overrides.
- Fix the `AVG LIFE 0:00` presentation at its semantic source. A nonzero
  measurable lifetime must render accurately; an unavailable/insufficient
  sample must render explicitly as unknown or insufficient, never as a false
  measured zero.
- Make `/kwr verify`, `/kwr perf`, and AAR derive from the same stability totals.
- Meet the task's reversal, pre-movement invalidation, median lifetime, and
  decisive-bypass acceptance thresholds without clearing or hiding bad data.

### 4. Implement KWR-034

- Keep raw localized Blizzard flag-event text in Last Events and AAR evidence.
- Normalize flag facts inside the existing `ObjectiveIntel` boundary, using
  assigned battleground team truth rather than the character's native faction.
- Permit only canonical command targets: friendly carrier, enemy carrier,
  `Our FC`, `Enemy FC`, `Home`, `Mid`, or a reviewed map route/location.
- Reject raw prose, timestamps, pickup sentences, and unknown widget labels at
  the final action-target boundary for `REINFORCE`, `ROTATE`, `HOLD`, and
  `COVER`.
- When normalization cannot establish a canonical target, emit a conservative
  verify/hold action and preserve uncertainty.
- Test Alliance/Horde assigned sides, native and cross-faction/mercenary
  orientation, pickup/drop/return/capture/reset semantics, and unknown or
  unrecognized localized input.

### 8. Safety and performance protocol

Use the current Retail-safe procedure in the external test plan. At minimum:

- Enable taint logging before the secure-UI test and archive only relevant,
  sanitized lines.
- Exercise CombatRoster target/focus rows before combat, during combat, through
  nameplate churn, and after combat.
- Request MainWindow, Quick Calls, and CombatRoster visibility/context changes
  during lockdown. Protected attributes, hierarchy, visibility, and row order
  must not mutate in combat; the final requested state must apply exactly once
  after `PLAYER_REGEN_ENABLED`.
- Confirm each secure target/focus click acts only from the user's hardware
  click and affects the intended unit.
- Confirm each Quick Call left-click sends exactly one fixed Instance Chat
  phrase and right-click opens the compact fallback. Confirm neither path
  mutates secure attributes in combat and no automatic communication occurs.
- Capture matched addon-enabled and addon-disabled FPS trials with the same
  character, resolution, graphics, nameplates, and representative conditions.
- Warm the UI for five minutes, then record memory at start, after warm-up, and
  once per minute for 30 minutes. Preserve high-water and post-natural-GC
  retained values.
- Capture CPU/timing through `/kwr perf` during dense combat and tab/visibility
  changes.

Use these current release limits unless a newer authoritative decision in the
repository supersedes them:

- p95 refresh at or below `2 ms`;
- routine maximum below `4 ms`;
- hard failure for any addon refresh above `10 ms`;
- retained post-warm-up memory growth below `1 MB` over 30 minutes;
- median FPS loss below `1%` and 1% low FPS loss below `3%` relative to the
  matched addon-disabled trial;
- zero Lua errors, taint, blocked actions, forbidden actions, protected-row
  mutations, or secret-value faults.

## Stop and repair rules

Stop the current live certification run on the first Lua error, taint or blocked
action, required reload, fabricated fact, wrong team orientation, identity
merge, malformed command target, protected-row mutation, secure click failure,
unbounded refresh, or hard performance-budget breach. Capture the screen, run
`/kwr bug`, preserve logs and state, create or update a bounded task, repair it,
rerun the complete offline gate, build a new hashed candidate, and restart the
affected live evidence cells. Evidence from a superseded candidate cannot
certify the repaired candidate.
